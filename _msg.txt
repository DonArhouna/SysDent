fix(backoffice): l ecran s ouvrait sur une etape 2FA impossible a terminer

`partialize` persistait `challenge2fa`. Un jeton d etape est a usage unique et de
courte duree : conserve dans `localStorage`, il fait que l ecran de connexion
s ouvre **directement** sur « Verification en deux etapes » au chargement, sans
qu aucune connexion ait eu lieu. Le jeton y est deja consomme ou expire, donc
aucun code a 6 chiffres ne peut jamais passer.

Symptome vu par le proprietaire : le backoffice redirige vers le formulaire de
verification alors qu il n a jamais recu - et ne recevra jamais - de code. Ses
identifiants etaient corrects, et son compte n avait meme aucun secret TOTP : le
backend renvoyait bien un jeton d enrollement, que le store ne pouvait pas
confondre. Seule la copie locale d un jeton de la session precedente expliquait
l affichage.

C est le meme argument que celui deja pose pour le jeton d enrollement, applique
a l autre moitie du meme mecanisme : un porte-credential d etape ne doit pas
survivre a la fermeture de l onglet.

`partialize` ne conserve plus que `token`, `refreshToken` et `profil`.

Preuve : 2 tests de persistance. Injection de defaut - remettre `challenge2fa`
dans `partialize` - fait echouer le test (1 echec sur 17), puis 17 verts apres
remise. `npm run verifier` vert : contrat a jour, 0 warning, 0 erreur.

**Au proprietaire** : vider le stockage local du backoffice une fois, le jeton
obsolete y est deja ecrit. DevTools, onglet Application, Local Storage, cle
`sysdent-backoffice-auth`, puis recharger.
