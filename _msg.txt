fix(backoffice): le jeton d activation partait dans le corps JSON, pas dans l en-tete

Le store appelait
`api.post('/platform/auth/2fa/activation', { code, bearer: jeton })`.
Or la signature est `api.post(chemin, corps, options)` : `bearer` tombait dans le
**corps**. L en-tete `Authorization` n etait donc jamais pose, et le backend
repondait « Authentification requise. ».

La preparation, elle, fonctionnait : `api.get(chemin, options)` - son second
argument *est* les options. D ou le symptome exacte : QR code affiche, puis
activation refusee.

**Les tests validaient le defaut.** Deux assertions affirmaient
`toHaveBeenCalledWith(chemin, { code, bearer })` : la forme du defaut. Elles
passaient donc depuis que la fonction avait ete ecrite, en attestant qu un jeton
envoye dans le JSON et un en-tete absent etaient le comportement attendu. C est
la limite de mocker `api` : on verifie l intention de l appelant, pas la requete.

Les deux assertions sont recalees sur le vrai contrat - `bearer` dans le
**troisieme** argument - et une troisieme couche existe deja : `api.test.ts`
intercepte `fetch` et lit l en-tete reellement emis, ce que le mock de store ne
peut pas faire.

Preuve par injection de defaut : remettre `bearer` dans le corps fait echouer 2
tests sur 22 ; restaure, 22 verts. `npm run verifier` vert : contrat a jour, 0
warning, 0 erreur.
